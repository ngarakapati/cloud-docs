= Connect with pyTigerGraph
:experimental:

pyTigerGraph provides Python applications with programmatic access to TigerGraph databases.
Applications can use the client to inspect schemas, read and write graph data, run queries, execute loading jobs, and perform administrative operations.

This page describes how to install pyTigerGraph, connect it to a Savanna workspace, and use its primary database functions.

== What is pyTigerGraph?

link:https://pypi.org/project/pyTigerGraph/[pyTigerGraph^] is the supported Python client library for TigerGraph.
It provides synchronous and asynchronous interfaces to the REST{plus}{plus} and GSQL APIs.
An application creates a `TigerGraphConnection` with the Savanna workspace URL, graph name, and database secret, then invokes methods on that connection.
The library runs within the application process and does not require a separate service.

For the complete API reference, see the link:https://www.tigergraph.com/docs/pytigergraph/current/intro/[pyTigerGraph documentation^].
This page focuses on the connection values and authentication requirements specific to Savanna.

== Capabilities

pyTigerGraph supports the following application workflows:

* *Schema management.* Create graphs, inspect schemas, and manage vertex and edge types.
* *Graph data access.* Retrieve vertices and edges, traverse relationships, and upsert graph data.
* *Query execution.* Run installed or interpreted GSQL queries and process their results as Python objects.
* *Data loading.* Create and execute loading jobs and monitor their status.
* *Vector and graph data science operations.* Manage vector attributes, upsert embeddings, perform similarity searches, and stream graph data into supported Python frameworks. See the link:https://www.tigergraph.com/docs/pytigergraph/current/gds/[GDS documentation^].

== Prerequisites

* A running Savanna xref:savanna:workgroup-workspace:workspaces/workspace.adoc[workspace] with an attached database. If necessary, xref:first-graph-ui.adoc[build a graph in Savanna] before continuing.
* A database secret for that database. See xref:savanna:administration:settings/how2-create-database-secret.adoc[Create a database secret].
* Python and `pip` installed in the application environment.
* The application's source IP address on the workgroup allowlist, if an allowlist is enabled. See xref:savanna:workgroup-workspace:workgroups/how2-config-network-access.adoc[Configure network access].

== Install

[source,bash]
----
pip install pyTigerGraph
----

The package also provides `AsyncTigerGraphConnection` for asynchronous applications.
The following examples use the synchronous `TigerGraphConnection` client.

== Configure the connection

A connection to Savanna requires the workspace URL, graph name, and database secret.

[cols="1,1,2",options="header"]
|===
|Argument |Required |What to use

|`host`
|Yes
|The Savanna workspace URL, including `https://`. In Savanna, open *Workspaces*, select the workspace, and copy its URL. The URL has the format `https://<workspace-id>.i.tgcloud.io`.

|`gsqlSecret`
|Yes
|A database secret for that workspace's database. See xref:savanna:administration:settings/how2-create-database-secret.adoc[Create a database secret].

|`graphname`
|Yes
|The graph that the connection targets. If the graph does not exist, create it in xref:savanna:graph-development:design-schema/index.adoc[Design Schema].
|===

Savanna exposes REST{plus}{plus} and GSQL over HTTPS port `443`.
For hosts containing `tgcloud`, pyTigerGraph selects this port automatically.
Retain the default values for `restppPort` and `gsPort`.

== Connect

Read the connection values from environment variables and create the connection:

[source,python]
----
import os
from pyTigerGraph import TigerGraphConnection

conn = TigerGraphConnection(
    host=os.environ["TG_HOST"],
    graphname=os.environ["TG_GRAPHNAME"],
    gsqlSecret=os.environ["TG_SECRET"],
)

print(conn.echo())
print(conn.getVertexTypes())
----

`echo()` verifies that the workspace host is reachable.
`getVertexTypes()` verifies authentication and graph access by returning the vertex types defined in the graph.

[CAUTION]
====
Store the database secret outside application code. It remains valid until it is deleted or revoked.
pyTigerGraph operations run against the connected database and can modify or delete graph data.
====

== Use common functions

The examples in this section use resource names from the connected graph.
Create the required schema, query, or loading job before executing an example, then retrieve and pass its name to the relevant method.
For the complete method list, parameters, and return values, see the link:https://www.tigergraph.com/docs/pytigergraph/current/intro/[pyTigerGraph documentation^].

=== Read the schema

Before retrieving schema metadata, xref:first-graph-ui.adoc[build a graph] or define one with xref:savanna:graph-development:design-schema/index.adoc[Design Schema].
`getSchema()` returns the graph schema.
`getVertexTypes()` and `getEdgeTypes()` return the available type names.
`getVertexCount()` and `getEdgeCount()` return the number of instances for specified types.

Parameter and return details: link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/schema[Schema functions^], link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/vertex[Vertex functions^], and link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/edge[Edge functions^].

[source,python]
----
schema = conn.getSchema()
vertex_types = conn.getVertexTypes()
edge_types = conn.getEdgeTypes()

vertex_type = vertex_types[0]
attributes = conn.getVertexAttrs(vertex_type)

print(vertex_type)
print(attributes)
print(conn.getVertexCount(vertex_type))
----

`getVertexAttrs()` returns `(attribute_name, attribute_type)` pairs.
Use the returned attribute names in `select`, `where`, and upsert dictionaries.

=== Read vertices and edges

The graph must contain data before these methods return records. See xref:savanna:graph-development:load-data/index.adoc[Load data].
`getVerticesById()` retrieves a vertex by primary ID.
`getVertices()` filters one vertex type by attributes from `getVertexAttrs()`.
`getEdges()` retrieves edges originating from a specified vertex. The edge type must be returned by `getEdgeTypes()`, and its endpoints must match `getEdgeSourceVertexType()` and `getEdgeTargetVertexType()`.

[source,python]
----
vertex_type = conn.getVertexTypes()[0]
attribute_name = conn.getVertexAttrs(vertex_type)[0][0]

one_vertex = conn.getVerticesById(vertex_type, "YOUR_PRIMARY_ID")

matching_vertices = conn.getVertices(
    vertex_type,
    select=attribute_name,
    where=f'{attribute_name}="YOUR_VALUE"',
)

edge_type = conn.getEdgeTypes()[0]
neighbors = conn.getEdges(
    sourceVertexType=vertex_type,
    sourceVertexId="YOUR_PRIMARY_ID",
    edgeType=edge_type,
)
----

Replace `YOUR_PRIMARY_ID` and `YOUR_VALUE` with values that exist in the connected graph.
To return a pandas `DataFrame`, use `getVertexDataFrame()` or `getEdgesDataFrame()`.
Full signatures: link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/vertex[Vertex functions^] and link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/edge[Edge functions^].

=== Add or update vertices and edges

An upsert creates a record if it does not exist or updates the existing record.
The vertex type, edge type, and attribute names must already exist in the schema from the previous section.
Create missing types in xref:savanna:graph-development:design-schema/index.adoc[Design Schema] before invoking these methods.

[source,python]
----
vertex_type = conn.getVertexTypes()[0]
attribute_name = conn.getVertexAttrs(vertex_type)[0][0]

conn.upsertVertex(vertex_type, "YOUR_PRIMARY_ID", {attribute_name: "YOUR_VALUE"})

edge_type = conn.getEdgeTypes()[0]
source_type = conn.getEdgeSourceVertexType(edge_type)
target_type = conn.getEdgeTargetVertexType(edge_type)
# If either method returns a set, select the endpoint type used by the target vertices.

conn.upsertEdge(
    sourceVertexType=source_type,
    sourceVertexId="YOUR_SOURCE_ID",
    edgeType=edge_type,
    targetVertexType=target_type,
    targetVertexId="YOUR_TARGET_ID",
    vertexMustExist=True,
)
----

`vertexMustExist=True` creates the edge only if both endpoint vertices exist.
`upsertVertices()`, `upsertEdges()`, `upsertVertexDataFrame()`, and `upsertEdgeDataFrame()` apply the same rules to a batch or a pandas `DataFrame`.
Column names must match the attribute names from `getVertexAttrs()` or `getEdgeAttrs()`.
See link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/vertex[Vertex functions^] and link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/edge[Edge functions^].

=== Run an installed query

. Write the query in the xref:savanna:graph-development:gsql-editor/index.adoc[GSQL Editor]. See xref:savanna:graph-development:gsql-editor/how2-edit-gsql-query.adoc[edit and run a query] and the https://www.tigergraph.com/docs/gsql-ref/4.3/querying/[GSQL query language^].
. Install the query from the Query List. `runInstalledQuery()` can call only an installed query.
. Retrieve the installed query name with `getInstalledQueries()`.
. Retrieve its parameter definitions with `getQueryMetadata()`, then pass those parameter names in `params`.

[source,python]
----
print(conn.getInstalledQueries())
print(conn.getQueryMetadata("YOUR_INSTALLED_QUERY"))

result = conn.runInstalledQuery(
    "YOUR_INSTALLED_QUERY",
    params={"YOUR_PARAMETER": "YOUR_VALUE"},
)
print(result)
----

Replace `YOUR_INSTALLED_QUERY` with a name returned by `getInstalledQueries()`, and replace `YOUR_PARAMETER` with a parameter returned by `getQueryMetadata()`.
Argument formats for strings, sets, and vertex parameters are in link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/query[Query functions^].

=== Run a loading job

. Define the vertex and edge types in xref:savanna:graph-development:design-schema/index.adoc[Design Schema].
. Create the loading job in xref:savanna:graph-development:load-data/index.adoc[Load data], including its file variable (`DEFINE FILENAME`).
. Confirm the job name with `getLoadingJobs()`. Set `fileTag` to the job's file variable, not the local filename.

[source,python]
----
jobs = conn.getLoadingJobs()
print(jobs)

result = conn.runLoadingJobWithFile(
    filePath="YOUR_LOCAL_FILE.csv",
    fileTag="YOUR_DEFINE_FILENAME",
    jobName="YOUR_LOADING_JOB",
    sep=",",
)
print(result)
----

`runLoadingJobWithData()` accepts file content as a string.
`runLoadingJobWithDataFrame()` accepts a pandas `DataFrame` whose columns follow the job's mapping.
`getLoadingJobStatus()` returns the status of a job run.
Remove the header row before loading the data. A `USING HEADER="true"` clause in the loading job does not replace this requirement.
Signatures: link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/loading[Loading job functions^].

=== Run a GSQL statement

Use `gsql()` for operations that do not have a dedicated pyTigerGraph method, such as displaying queries created in the GSQL Editor.
The connection's graph is the default graph. GSQL syntax is in the https://www.tigergraph.com/docs/gsql-ref/4.3/querying/[GSQL query language^], and the method contract is in link:https://www.tigergraph.com/docs/pytigergraph/current/core-functions/gsql[GSQL interface^].

[source,python]
----
print(conn.gsql(f"USE GRAPH {conn.graphname} SHOW QUERY ALL"))
----

In application code, use the method specific to the required operation: `getSchema()` to retrieve a schema, `runInstalledQuery()` to execute an installed query, and `runLoadingJobWithFile()` to execute a loading job.

== Troubleshooting

=== Invalid URL scheme

`host` needs `http://` or `https://`.
For Savanna, use `https://<workspace-id>.i.tgcloud.io`.
A hostname alone raises `Invalid URL scheme`.

=== Authentication failed

Create a database secret for the target workspace and pass its complete value as `gsqlSecret`.
A control-plane API key authenticates the xref:savanna:rest-api:index.adoc[Savanna REST API] and will not authenticate this connection.
See xref:savanna:administration:settings/how2-create-database-secret.adoc[Create a database secret].

=== Connection error

Verify the following:

* The workspace status is active
* `host` is that workspace's URL, including `https://`
* `gsqlSecret` is a database secret for that workspace
* `graphname` matches a graph in that database
* The application's source IP address is on the workgroup allowlist, if an allowlist is enabled

See xref:savanna:workgroup-workspace:workspaces/workspace.adoc[About workspaces] and xref:savanna:workgroup-workspace:workgroups/how2-config-network-access.adoc[Configure network access].
